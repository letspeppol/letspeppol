# Open questions

Building this catalogue meant looking at every component on its own, in both themes, four languages and six screen
sizes. These are the inconsistencies and gaps that turned up. Each one needs a decision, not necessarily a change.
Counts are from `src/` on 5 November 2026.

## Shared styles that pages copy instead of use

<div className="ds-stack" style={{ margin: '1rem 0 2rem' }}>
  <div className="ds-rule note"><span className="ds-rule-kind">Notice</span><div className="ds-rule-body"> The global <code>.notice</code> (info, warn, danger, ok) has no users. Settings ships <code>settings-notice</code> and the wizard ships <code>wizard-notice</code>. Pick one notice and use it everywhere? See Primitives/Status and feedback.</div></div>
  <div className="ds-rule note"><span className="ds-rule-kind">Span</span><div className="ds-rule-body"> <code>.span-2</code> is unused while <code>settings-span-2</code> and <code>partner-span-2</code> do the same job locally.</div></div>
  <div className="ds-rule note"><span className="ds-rule-kind">No-wrap</span><div className="ds-rule-body"> There is no shared rule to keep references, ids and dates on one line, so pages add their own (<code>partner-nowrap</code>, <code>download-date</code>). Without it, INV-2026-0141 breaks at the hyphen in narrow columns. See Primitives/Data table.</div></div>
  <div className="ds-rule note"><span className="ds-rule-kind">Unused</span><div className="ds-rule-body"> <code>.card-header</code>, <code>.grid-col-73</code> and <code>.display</code> are defined in the global stylesheet but not used by any template. Keep, use or remove?</div></div>
</div>

## Tokens

<div className="ds-stack" style={{ margin: '1rem 0 2rem' }}>
  <div className="ds-rule note"><span className="ds-rule-kind">Aliases</span><div className="ds-rule-body"> About fifty legacy aliases (<code>--primary</code>, <code>--panel</code>, <code>--space-05</code>, <code>--radius-lg</code>, the <code>--pill-</code> and <code>--status-</code> sets…) are still defined, but only 12 references in 5 CSS files use them (<code>--space-05</code> 6, <code>--space-2rem</code> 2, <code>--panel</code>, <code>--space-075</code>, <code>--space-125</code>, <code>--white</code> 1 each). The layout helpers <code>--sidebar-width</code>, <code>--sticky-offset</code>, <code>--search-min-w</code>, <code>--composer-min</code>, <code>--total-min</code> and <code>--pos-col-w</code> have no users at all. Migrating the 12 would let the whole block go.</div></div>
  <div className="ds-rule note"><span className="ds-rule-kind">Contract</span><div className="ds-rule-body"> <code>--navy-ink</code> (23 uses), <code>--rule-strong</code> (18) and <code>--danger-fill</code> (4) are real, well-used tokens but missing from the token table in DESIGN.md. Foundations/Colour shows them; the contract should list them too.</div></div>
  <div className="ds-rule note"><span className="ds-rule-kind">Pills</span><div className="ds-rule-body"> Pill modifiers are named after domain states, two per colour (<code>sent</code>/<code>incoming</code>, <code>processed</code>/<code>paid</code>, <code>error</code>/<code>overdue</code>), while notices use semantic names (<code>info</code>, <code>ok</code>, <code>warn</code>, <code>danger</code>). Partners even reuse them for partner types (<code>pill sent</code> for Customer, <code>pill incoming</code> for Supplier). One vocabulary for both would make new statuses obvious.</div></div>
</div>

## Controls

<div className="ds-stack" style={{ margin: '1rem 0 2rem' }}>
  <div className="ds-rule note"><span className="ds-rule-kind">Invalid</span><div className="ds-rule-body"> Only selects get a red outline when required and empty (<code>.field.missing-required select</code>). Text inputs have no invalid style; the message under the form carries the error alone. Should invalid inputs look invalid? See Primitives/Fields, States.</div></div>
  <div className="ds-rule note"><span className="ds-rule-kind">Icons</span><div className="ds-rule-body"> Icons are pasted inline: 98 use a 2px stroke, 22 use 1.5px, three more use 2.25 or 3. <code>nav-icon</code> already centralises navigation icons; a shared icon element for the rest would keep size and stroke consistent.</div></div>
</div>
