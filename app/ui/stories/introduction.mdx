# Let’s Peppol design system

This is the living catalogue of the `app/ui` interface: every token, shared style and component the app uses, rendered
from the real source with demo data. Nothing here is a mock-up. When the code changes, this changes.

Use it to look at one piece at a time, to compare it across themes, languages and screen sizes, and to agree on how the
interface should behave before anyone writes a ticket.

Every component has an **Overview** page with its guideline text and all its states side by side.

## The toolbar

- **Theme**: light or dark. Both themes are first-class; review both.
- **Language**: English, Nederlands, Français, Deutsch. German and French are the stress test for long labels.
- **Viewport**: small phone 360, phone 390, phone landscape 844×390, tablet portrait 820, tablet landscape 1180,
  desktop 1440. Layouts switch at the same breakpoints as the app.
- **Accessibility** panel (bottom): automated axe checks for the story on screen.

## Discussing a design

1. Open the story, set theme, language and viewport, and copy the URL from the address bar. The link keeps those settings.
2. Say what you see and what you expect, with the rule from **Foundations** it touches (or that is missing).
3. Proposals become a new story next to the existing one, so both can be compared before the component changes.

## Running it

```sh
cd app/ui
npm run storybook        # http://localhost:6006
npm run build-storybook  # static site in storybook-static/, can be hosted anywhere
```

Stories live in `app/ui/stories`. Components with injected services get fake services from
`stories/support/mocks`, so no backend, database or login is needed.
