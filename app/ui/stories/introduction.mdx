# Let’s Peppol design system

This is the living catalogue of the `app/ui` interface: every token, shared style and component the app uses, rendered
from the real source with demo data. Nothing here is a mock-up. When the code changes, this changes.

Use it to look at one piece at a time, to compare it across themes, languages and screen sizes, and to agree on how the
interface should behave before anyone writes a ticket.

Every entry in the sidebar is one page: the guideline text for a component followed by all its states. Phone and tablet
states are shown at their real width.

## Reviewing

Go through the pages top to bottom. Switch **Theme** and **Language** in the toolbar: both themes are first-class, and
German and French are the stress test for long labels. Start with **Open questions**, where a decision is needed.

## Giving feedback

1. Open the page the feedback is about.
2. Press **Give feedback** in the toolbar. It opens a GitHub issue with the page, link, theme and language filled in.
3. Finish the title, say what you see and what you expect, and submit.

**Feedback on this page** lists what is already open for the page, so you can add to an existing issue instead of
opening a second one. [All open design feedback](https://github.com/letspeppol/letspeppol/issues?q=is%3Aissue+is%3Aopen+in%3Atitle+%22Design+feedback%22)
is the list for the whole catalogue.

## What happens with feedback

Each issue is closed with either a change to the interface or a decision written into the page it is about. When no
design feedback is open any more, this catalogue is turned into the design document of the application, served next to
the API docs.

## Running it

```sh
cd docker/local
docker compose up -d --build   # http://localhost:3002, next to the application on http://localhost:3001
```

or, without Docker:

```sh
cd app/ui
npm install
npm run storybook              # http://localhost:6006
```

Pages live in `app/ui/stories`. Components with injected services get fake services from `stories/support/mocks`, so no
backend, database or login is needed.
